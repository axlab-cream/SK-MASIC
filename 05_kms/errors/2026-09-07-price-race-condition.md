# 2026-09-07 · 조건부 가격이 상시가로 저장된 경쟁 상태 (오류)

> 분류: errors · 심각도: **높음 (표시광고법 위반 직행)** · 프로젝트: SK MASIC

## 무엇이 일어났나

카드 리스트 배너에 `MEGA ICE 얼음정수기 mini · 21,950원` 이 찍혔다.
그런데 고지문에는 "최초 18개월 적용" 문장이 **없었다.**

21,950원은 **최초 18개월만** 적용되는 가격이고 19개월차부터 43,900원이다.
조건 없이 이 숫자를 광고하면 오인 표시다. 배너는 QA 8항목을 전부 통과한 상태였다.

## 어떻게 발견했나

렌더된 PNG 를 직접 눈으로 확인하다가, **가격과 고지문이 서로 맞지 않는다**는 점이 보였다.
- 조건부 가격을 표시하면 고지문에 조건이 자동으로 들어가도록 설계(D-33)해 놨는데 없었다
- 즉 엔진은 "이 가격은 조건부가 아니다" 라고 믿고 있었다

카탈로그를 확인하니 `sale: 21950, promoPrice: null, promoTerms: null` 이었다.
같은 상품이 **1차 수확에서는** `sale: 43900, promoPrice: 21950, promoTerms: {18개월…}` 이었다.

## 원인

상세 페이지는 **라벨을 먼저 그리고 값을 비동기로 채운다.**
수확기는 `기준 구독료` 라벨이 나타나면 곧바로 `document.body.innerText` 를 읽었다.

값이 덜 채워진 순간의 텍스트는 이런 모양이 된다.

```
기준 구독료
월 62,900 원
기본 할인가          ← 값이 아직 없다
최종 할인가
월 21,950 원         ← "기본 할인가" 뒤 80자 안에서 이게 먼저 잡힌다
```

`after('기본 할인가', 80)` 이 21,950 을 집어 `sale` 로 저장했다.
그리고 `최종 할인가` 값은 이미 소비됐으므로 `promo` 는 비었고, 조건 문장도 함께 사라졌다.

**타이밍에 따라 결과가 달라지는 추출이었다.** 1차 수확이 우연히 맞았기 때문에 검증을 통과했다.

## 수정

| 층 | 내용 |
|---|---|
| 대기 | 가격 블록 **끝**(`방문주기 :` / `의무사용 N개월`)까지 기다린다. 첫 라벨만으로는 부족하다 |
| 안정성 | 최대 3회·0.9초 간격으로 읽어 **두 번 연속 동일**할 때만 채택 (`readStable`) |
| 모양 검사 | `sale ≤ base`, `promo ≤ sale`, 최종 할인가 라벨이 있으면 조건도 필수, `promo === sale` 이면 오독 |
| 폐기 | 불안정하면 base·sale·promo 전부 `null` (`priceStable: false`) → 배너는 "상담 시 안내" |
| QA 그물 | `price_condition` 항목 신설. 조건부 가격을 표시했는데 조건 문장이 없으면 **실패** |
| QA 대상 | `gate()` 가 `buildNotice()` 를 다시 부르지 않고 **렌더된 `[data-slot="notice"]` 텍스트**를 검사 |

## 교훈

1. **비동기로 채워지는 값을 한 번 읽는 것은 추출이 아니라 도박이다.** 두 번 같게 읽히는지 확인해야 한다
2. **검증은 산출물을 봐야 한다.** `gate()` 가 고지문을 다시 만들어 검사하면 자기 자신을 검사하는 셈이고,
   실제 화면과 어긋난 순간을 절대 잡지 못한다
3. **"없음" 이 "틀림" 보다 안전한 필드가 있다.** 가격이 그렇다. 미확정으로 남기면 MC 가 상담에서 안내하지만,
   틀린 조건부 가격은 회사가 책임진다
4. 이 결함은 **자리표시자·샘플 데이터로는 절대 드러나지 않는다.** 실제 페이지의 렌더 타이밍이 원인이기 때문이다
