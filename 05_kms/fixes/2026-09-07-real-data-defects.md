> 샘플 데이터로는 전부 통과했던 코드다. **실제 데이터가 통과시킨 테스트를 무너뜨렸다.**

## F-01 카테고리별 개수 제한이 전체 합계로 걸려 있었다
- 증상: "카테고리별 10개" 를 요청했는데 정수기 71건만 수집되고 나머지 카테고리는 아예 안 돌았다
- 원인: `if (limitPerCategory && found.size >= limitPerCategory) break;` — `found` 는 전체 누적 Map 이다.
  첫 카테고리에서 이미 10을 넘으므로 카테고리 루프가 즉시 끊겼다
- 수정: 카테고리별 `inCat` Map 을 따로 두고 각각 slice 한 뒤 병합
- 교훈: "per X" 제한은 **X 범위의 카운터**로 세야 한다. 전역 카운터로 세면 첫 X 만 처리된다

## F-02 가격을 정렬해서 골랐다 — 옆 상품 가격이 섞였다
- 증상: 상세 1페이지에서 금액 후보가 7~8개씩 나왔다 (관련 상품 5개의 가격까지 포함)
- 수정: `기준 구독료` / `기본 할인가` / `최종 할인가` **라벨 앵커** 뒤 80자 안의 금액만 채택.
  라벨을 못 찾으면 `null` 로 남기고 추정하지 않는다
- 교훈: 스크래핑에서 "가장 큰 값 / 가장 작은 값" 은 휴리스틱이 아니라 버그다. 라벨이 곧 계약이다

## F-03 조건부 가격을 조건 없이 쓸 뻔했다 (법적 리스크)
- 최종 할인가 25,950원은 **최초 18개월만** 적용되고 19개월차부터 51,900원이다
- 수정: `promoTerms`(개월·전환시점·전환후가) 가 함께 확보될 때만 `promoPrice` 를 저장하고,
  표시했을 때 고지문에 조건 문장이 자동으로 들어간다 (D-33)

## F-04 배지 가격과 고지문 기준이 서로 달랐다
- 증상: 배지는 43,900원(기본 할인가)인데 고지문은 "표시 구독료는 최초 18개월 적용, 19개월차부터 월 43,900원"
  — 프로모션가를 안 보여주면서 프로모션 조건을 고지했다. 그 자체가 오인 표시다
- 수정: 배지·행·히어로·합계가 **같은 기준**을 쓰도록 `heroOf(i)` 로 통일하고,
  `notice(products, { promoShown })` 로 표시 기준을 고지문에 전달

## F-05 제휴카드 할인 상한을 상품 수만큼 곱했다 (법적 리스크)
- 증상: 3종 배너에 "제휴카드 월 최대 84,000원 추가 할인" (28,000 × 3)
- 곱해진다는 근거가 없다. 수정: **금액 없이** "제휴카드 조건 충족 시 추가 할인" (D-35)
- 교훈: 합산이 정당한 값은 구독료뿐이다. 상한·한도는 합산 대상이 아니다

## F-06 실제 Chrome 에서 제품 사진이 alt 텍스트로 찍혔다
- 원인: `page.setContent()` → 페이지 출처 `about:blank` → 실제 Chrome 이 `file://` 하위 리소스 차단.
  번들 Chromium 에서는 통과했기 때문에 브라우저를 바꾼 뒤에야 드러났다
- 수정: 임시 파일 + `page.goto('file://...')`. 그리고 **QA 에 "제품 사진 로드" 항목 추가** (`naturalWidth > 0`).
  사진이 깨진 배너는 이제 통과할 수 없다 (D-36)
- 교훈: "사진이 없으면 자리표시자" 는 설계였지만 **"사진이 있는데 못 불러온 경우"** 는 설계에 없었다.
  없는 것과 실패한 것은 다르게 다뤄야 한다

## F-07 검증기가 nullable 필수 필드를 누락으로 처리했다
- 증상: 비데 4종·프레임 5종이 `care: 필수값 누락` 으로 제외 — 실제로 공식몰에 관리유형 표기가 없는 상품이다
- `care` 는 enum 에 `null` 이 있는데도 `required` 검사가 null 을 누락으로 봤다
- 수정: `type` 에 `"null"` 이 있거나 `enum` 에 `null` 이 있으면 null 을 통과시킨다
- 교훈: 값이 없는 것도 사실이다. 실제 상품을 목록에서 지우는 검증은 검증이 아니라 손실이다

## F-08 배너에 제품명이 없었다
